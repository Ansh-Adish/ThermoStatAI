# ThermoStatAI

Hyperlocal heat intelligence for home cooling — built on the FortyGuard Temperature API for the Global AI Hackathon '26.

**Live demo:** https://thermostat-ai.netlify.app

## The problem

Two homes three streets apart can face wildly different real thermal loads — downtown concrete vs. tree-canopy suburb — but both run their AC on the same generic schedule. That's wasted money and unnecessary grid strain during Phoenix's growing number of 110°F+ days.

## What this does

1. Pulls real hyperlocal heat and urban-heat-island data from the FortyGuard Temperature API for a given block.
2. Scores **thermal load** (not just raw air temperature) by combining ambient temperature, UHI intensity, and surface heat retention — because a cooler-but-more-paved block can carry a *higher* real cooling burden than a hotter-but-greener one.
3. Recommends a specific thermostat setpoint range and a pre-cooling window based on the observed lag between solar noon and peak air temperature, so a user can manually verify the recommendation before trusting any automation.
4. Shows a real, satellite-based heat-zone overlay image generated by FortyGuard for the block in question.

## How to run it from scratch

This is a static single-file HTML/CSS/JS app — no build step and no server required for the frontend demo.

```bash
git clone <this-repo-url>
cd ThermoStatAI
open index.html
```

You can also double-click `index.html` or drag it into a browser.

To redeploy to a live URL, deploy the project through Netlify.

### Fetching FortyGuard data yourself

`fetch_zones.py` shows the real integration pattern used to pull the data this demo is built on: submit an asynchronous job, poll for completion, and download the resulting PDF report.

```bash
pip install requests
python fetch_zones.py
```

Before running it, set your own FortyGuard API key in the script.

**Never commit a real API key to the repository.**

## What doesn't work yet

* **Only 3 Phoenix zones are wired up:** downtown, industrial, and suburb. Typing any other address shows an honest "not in this demo's coverage" message rather than faking a result.
* **"Connect my thermostat" is a UI mock**, not a real Nest/Ecobee OAuth integration. The mocked sequence (search → sync → confirm) demonstrates the intended UX.
* **The map/thermal data shown is pre-fetched and cached**, not queried live on each search. FortyGuard's API is an asynchronous process that can take several minutes per request, so a production version would run this on a schedule and serve cached results instantly.
* **Savings percentages are estimates**, positioned within the documented range for smart thermostats — not measured from real deployed users, since none exist yet.
* **Citywide dollar figures are estimates**, not guarantees.

## Real FortyGuard API request/response used in this project

**Request:**

```python
import requests

response = requests.post(
    'https://api.fortyguard.com/v1/heat_intelligence',
    headers={'api-key': 'your_api_key'},
    json={
        'latitude': 33.4484,
        'longitude': -112.0740,
        'temperature': 112.0,
        'date': '2026-08-29',
        'analysis': ['environmental']
    }
)
```

**Response:**

```json
{
  "error": false,
  "status_code": 200,
  "message": "Heat Intelligence Submitted Successfully",
  "data": {
    "activity_id": "6032cb6a-dc2b-49a7-abad-3846cd142274"
  }
}
```

This starts an asynchronous job. The project polls the returned activity ID until the report is completed, then downloads the resulting FortyGuard Heat Intelligence Report containing the metadata, satellite map imagery, and environmental/climate analysis used by the project.
